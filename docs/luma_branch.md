# Эксперимент luma

Конфиг [configs/luma.yaml](../configs/luma.yaml) наследует `positive_dice` и добавляет лёгкую яркостную ветку 1024. Цель — проверить, можно ли использовать детали до уменьшения RGB до 640 без CPU residual-карт из `local`. Полное обучение пока не выполнялось; улучшение Dice не установлено.

Дополнение после замера реального training loop: **при batch 2, accumulation 8, BF16 на RTX 3070 luma занимает 156 мс/батч против 113 мс у positive_dice (+38%)**. Это измерено после прогрева с настоящим train-loader и подтверждено GPU replay. Малое увеличение FLOPs не означает малое увеличение времени обучения. Ветка добавляет около 17 мс forward и 26 мс backward; её GroupNorm возвращает FP32 в текущем AMP-режиме, а depthwise 5×5 на 1024 имеет дорогой backward. Пик выделенной PyTorch-памяти в replay: 3.11 против 2.53 GiB. Диагностическая смена layout только ветки дала 143–144 мс/батч и 2.94 GiB; в рабочий код не внесена. [Полный аудит и условия замеров](../runs/luma_setup_20260909/training_timing.md).

## Данные и модель

Изображение читается один раз. После общей геометрии и photometric-аугментаций CPU сохраняет native RGB как uint8 CHW. Кадры переменного размера передаются списком без padding. На GPU вычисляется `Y = (0.299R + 0.587G + 0.114B) / 255` в float32, затем напрямую уменьшается/увеличивается до 1024. Это сохраняет детали уровня диагностического входа 1024, а не всю информацию произвольного исходного разрешения.

Основная сеть получает привычные RGB640 и DCT. Дополнительная ветка: convolution 1→8, параллельные depthwise-фильтры 3×3 и 5×5, два уменьшения до 16/24 каналов, проекция и одно аддитивное слияние с финальными признаками EMCAD. Отдельного encoder/decoder нет. Фильтры обучаемые, без принудительных abs/energy преобразований; это не фиксированный wavelet или гарантированно высокочастотный фильтр.

Коэффициент слияния начинается с нуля. Вспомогательная маска предсказывается непосредственно из яркостной ветки и получает существующий auxiliary loss вместо вспомогательной головы EMCAD. Поэтому она учится с первого шага, независимо от encoder и нулевого начального коэффициента. Основной классификационный gate остаётся глобальным.

`local` также читает изображение один раз, но строит на CPU 15 каналов RGB/residual и передаёт 30 MiB на кадр при BF16/1024. `luma` передаёт native uint8 RGB: `3×H×W` байт. На больших исходниках этот объём и временная GPU-память растут. Native-препроцессинг выполняется последовательно для кадров списка; он не бесплатен. Для ограничения очередей установлены prefetch=1 и validation batch, равный train batch.

## Запуск

В [notebooks/train.ipynb](../notebooks/train.ipynb) выбрать `experiment = "luma"`, либо из корня:

```powershell
& 'D:/Apps/anaconda3/envs/challenges/python.exe' -m src.training --config configs/luma.yaml
```

Результат попадёт в `runs/luma` (при занятом имени — с суффиксом). Настройки оборудования берутся из `.env`/переменных среды. Рецепт наследует 6×24000 показов, positive Dice, EMA и обычный mixed-frame train. Ветки `local`/`luma` и дополнительные decoder refinements взаимоисключающие; геометрия — stretch. Поддержаны обучение, EMA, resume, checkpoint evaluation, Predictor и submission.

Для сравнения запускать `positive_dice` и `luma` с одинаковыми seed, batch, accumulation и AMP. В `luma`, как в `local`, photometric применяется до resize, чтобы оба пути видели одну аугментацию; в baseline — после resize. Поэтому сравнение рецептов включает этот фактор, а не только архитектуру. При положительном результате нужен контроль с тем же порядком аугментаций и отключённой яркостной веткой.

Выбирать checkpoint по development AIC; дополнительно сравнивать Dice малых масок ≤1%, долю предсказаний без пересечения и результат без classification gate. Holdout использовать только по существующему протоколу после выбора эксперимента.

## Проверка реализации

Весь набор до финальной правки resume: **295 passed**. После неё прошли 52 теста веток, resume и losses, включая совместимость старых flat/nested snapshots без нового поля и совпадение submission с checkpoint evaluator на синтетических изображениях. Независимое ревью выполнено, найденная несовместимость resume исправлена.

Скрипт [check.py](../runs/luma_setup_20260909/check.py) и [verification.json](../runs/luma_setup_20260909/verification.json) содержат воспроизводимую проверку на восьми train-кадрах и два временных шага обучения со случайных весов, без checkpoint. CPU-замер: один поток, два прохода в чередующемся порядке, без аугментаций; это не скорость эпохи. GPU smoke: RTX 3070, BF16, batch 2, конечные loss/параметры и ненулевой коэффициент слияния.

Полный eval forward по `FlopCounterMode`: **90.539 GFLOPs**, против 89.565 у основной сети. Счётчик не учитывает все операции, включая преобразование яркости и interpolation: одинаковые значения для разных native-размеров не означают одинаковую скорость. Отдельные CUDA-event замеры преобразования и передачи native-входа находятся в `gpu_preprocess` в JSON. Они исключают CPU-декодирование и основную модель. Время на H100 и соблюдение 50 мс пока не измерены.

Итоговый локальный замер 2026-09-09:

| Показатель | local | luma |
|---|---:|---:|
| CPU подготовка кадра, среднее | 74.92 мс | 24.57 мс |
| CPU дополнительные признаки / упаковка | 49.78 мс | 0.40 мс |
| Дополнительный вход, среднее по выбранным кадрам | 30 MiB | 1.13 MiB |

Передача pinned uint8 RGB + получение Y1024 на RTX 3070: 0.26 мс для native640², 0.45 мс для native1024², 1.08 мс для native1536×2048 (batch 1, среднее 20 повторов). Полный smoke обучения batch 2 использовал пиковые 2.83 GiB выделенной CUDA-памяти. Набор из восьми кадров ограничен размерами ≤1600 по каждой стороне; эти цифры нельзя переносить на самые большие исходники или H100 без замера. Артефакты `runs/` сохраняются локально согласно `.gitignore`.
